#### 🎯 使用 `compatibility` 欄位標註平台相容性

但是，**有些技能確實是為特定平台設計的**。這時用 `compatibility` 欄位標註清楚：

```yaml
---
name: hugo-blog-migrator
description: [你的描述]
compatibility: 需要 Python 3.10+；需要網路存取；
  部分功能僅支援 Claude Code（需要檔案系統權限）
---
```

### 🎭 **Positioning 技巧**：讓你的技能被看見、被採用

**官方警告：**
```
「如何描述你的技能，決定了使用者『是否理解其價值』、
  以及『是否真的會去試用』。」
```

這不是寫給 Claude 讀的 description（那是前言的事）。這是**寫給人類讀的介紹文案**——放在 README、文件、行銷素材裡。

#### 💎 三大文案黃金原則

---

##### 原則 1：聚焦「成果」，而不是「功能」

```
❌ 壞範例（聚焦功能）：
─────────────────────────────────────────────────
「ProjectHub skill 是一個包含 YAML 前言和 Markdown
  指令的資料夾，會呼叫我們的 MCP 伺服器工具。」
─────────────────────────────────────────────────

🤔 使用者讀完：「所以……？這對我有什麼好處？」
```

```
✅ 好範例（聚焦成果）：
─────────────────────────────────────────────────
「ProjectHub skill 讓團隊能在『數秒內』
  設定完整的專案工作區——包含頁面、資料庫、模板——
  而不是花 30 分鐘做手動設定。」
─────────────────────────────────────────────────

🎯 使用者讀完：「30 分鐘變幾秒？我要用！」
```

---

##### 原則 2：把「MCP + Skills」故事說清楚

```
❌ 壞範例（只提其中一個）：
─────────────────────────────────────────────────
「我們的 MCP 伺服器讓 Claude 能存取你的 Linear 專案。」
─────────────────────────────────────────────────

（使用者：所以我自己還是要學怎麼用？）
```

```
✅ 好範例（MCP + Skills 雙贏定位）：
─────────────────────────────────────────────────
「我們的 MCP 伺服器讓 Claude 能存取你的 Linear 專案。

  我們的 Skills 教 Claude 你們團隊的 sprint 規劃流程。

  合在一起，你得到的是『AI 驅動的專案管理』。」
─────────────────────────────────────────────────

🎯 使用者讀完：「原來是這樣——兩個一起用才是完整方案！」
```

### 🧯 **沒有蠢問題**

---

**Q：我一定要開源嗎？可以做「閉源技能」嗎？**

A：完全可以。開源只是其中一個選項。你可以：
- 只在公司內部分享（組織部署）
- 只發給付費客戶（私人 repo 或密封分發）
- 混合模式（核心開源、進階閉源）

技能本身就是一包資料夾，你想怎麼分發都行。

---

**Q：我的技能用了私有 API，可以上架嗎？**

A：可以上架技能本身，但**使用者需要自己拿到 API 金鑰**。你的技能可以引導他們去你的服務註冊、取得金鑰、設定 MCP。

---

**Q：組織部署的技能，個別員工可以關掉嗎？**

A：根據官方資訊，組織部署是「工作區級」的。管理員控制技能的啟用，但使用者端通常可以**個別關閉**（避免過度觸發）。具體行為建議以 Claude 管理主控台最新文件為準。

---

**Q：我要把技能發到 Anthropic 的官方 repo 嗎？**

A：Anthropic 有一個 `anthropics/skills` GitHub repo，但那主要是**官方技能的範例**。你的技能應該：
1. 先放在自己的 GitHub
2. 如果有夥伴計畫（Partner Program），可以透過官方管道進入 Partner Skills Directory
3. Canva、Figma、Sentry、Zapier 等都在這個目錄裡

---

**Q：Skills、MCP、Plugin、Agent——這些到底怎麼分？**

A：這是 2026 年最常混淆的名詞。用一張表釐清：

```
┌──────────┬──────────────────────────────────────┐
│ 名稱     │ 角色                                    │
├──────────┼──────────────────────────────────────┤
│ MCP      │ 🔌 連線協定：讓 Claude 連到外部服務      │
│          │                                        │
│ Skill    │ 📜 指令集：教 Claude 怎麼做事           │
│          │                                        │
│ Plugin   │ 📦 分發包裝：把 Skills/MCP 整合成       │
│          │    一個可安裝的套件                      │
│          │                                        │
│ Agent    │ 🤖 完整應用：Claude + Skills + MCP +   │
│          │    使用者任務的完整系統                   │
└──────────┴──────────────────────────────────────┘
```
