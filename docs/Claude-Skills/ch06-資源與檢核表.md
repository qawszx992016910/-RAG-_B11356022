##### 💪 三大能力

**能力 1：從描述「生成」技能**

```
你說：
「幫我建一個把 WordPress 遷移到 Hugo 的技能」

skill-creator：
✅ 產出符合格式的 SKILL.md + YAML 前言
✅ 建議觸發短語
✅ 建議資料夾結構
```

---

**能力 2：「審查」現有技能**

```
你說：
「幫我看看這個技能有沒有什麼問題」

skill-creator：
✅ 指出描述模糊的問題
✅ 識別觸發詞缺漏
✅ 指出結構問題
✅ 預警過度觸發 / 觸發不足風險
✅ 根據目的建議測試案例
```

---

**能力 3：「迭代」改進**

```
你說：
「用這個對話裡發現的問題和解法，
  改善我技能處理 [特定邊界情境] 的方式」

skill-creator：
✅ 根據真實的失敗案例改進
✅ 補強原本漏掉的情境
```

### 📝 Reference B：YAML 前言完整參考

---

#### ✨ 最小必要格式

```yaml
---
name: skill-name-in-kebab-case
description: 這技能做什麼、以及何時使用它。包含具體的觸發短語。
---
```

**這是最小可行的前言**——只要有這兩行，技能就能動。

---

#### 🎨 完整可用欄位

```yaml
---
name: skill-name                          # 必填
description: [必填 - 描述]                 # 必填
license: MIT                              # 選填：開源授權
allowed-tools: "Bash(python:*) Bash(npm:*) WebFetch"  # 選填：限制工具存取
metadata:                                 # 選填：自訂欄位
  author: Company Name
  version: 1.0.0
  mcp-server: server-name
  category: productivity
  tags: [project-management, automation]
  documentation: https://example.com/docs
  support: support@example.com
compatibility: "需要 Python 3.10+、GitHub MCP 存取權"  # 選填：1-500 字元
---
```

---

#### 🔍 欄位逐項速查

```
┌─────────────────┬─────────┬───────────────────────────────┐
│ 欄位            │ 必填？  │ 重點                            │
├─────────────────┼─────────┼───────────────────────────────┤
│ name            │ ✅ 必填  │ kebab-case、無空格、無大寫       │
│                 │         │ 不可含 claude / anthropic       │
├─────────────────┼─────────┼───────────────────────────────┤
│ description     │ ✅ 必填  │ < 1024 字元、無 < > 符號        │
│                 │         │ 包含 WHAT + WHEN                │
├─────────────────┼─────────┼───────────────────────────────┤
│ license         │ ⭕ 選填  │ MIT、Apache-2.0 等              │
│                 │         │ 開源時使用                       │
├─────────────────┼─────────┼───────────────────────────────┤
│ allowed-tools   │ ⭕ 選填  │ 限制技能可用的工具                │
│                 │         │ 格式：Bash(cmd:*)、WebFetch     │
├─────────────────┼─────────┼───────────────────────────────┤
│ compatibility   │ ⭕ 選填  │ 1-500 字元                      │
│                 │         │ 描述環境需求                     │
├─────────────────┼─────────┼───────────────────────────────┤
│ metadata        │ ⭕ 選填  │ 任意 key-value 對               │
│                 │         │ 推薦：author, version,          │
│                 │         │       mcp-server                │
└─────────────────┴─────────┴───────────────────────────────┘
```

**Q：我的技能做完後，怎麼保持它「活著」？**

A：三個維護策略：

```
1. 定期重讀 description
   → 使用者語言在變，你的觸發詞要跟上

2. 監控 API 變化
   → MCP 伺服器會更新，工具名稱可能改

3. 蒐集使用者回饋
   → Discord、GitHub Issues、團隊回報
   → 納入 skill-creator 迭代
```

**Q：我怎麼知道我的技能該升到幾版？**

A：用**語意化版本**（Semantic Versioning）：

```
v1.0.0
│ │ │
│ │ └─ Patch（修 bug、小改 description）
│ └─── Minor（新增功能、新增觸發詞）
└───── Major（不相容變更、工作流大改）

範例：
▸ v1.0.0 → v1.0.1  修錯字、微調描述
▸ v1.0.1 → v1.1.0  新增一個步驟、支援新檔案類型
▸ v1.1.0 → v2.0.0  把順序工作流改成 Multi-MCP 架構
```
