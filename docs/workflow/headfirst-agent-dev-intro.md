# 🤖 Head First: Agent-Driven Development
## SDD × BDD × TDD 工作流完全指南

---

## 🎬 開場：你遇過這個問題嗎？

你對 AI Agent（Claude Code、ChatGPT）說：

> 「幫我做使用者登入功能。」

Agent 的反應很快，5 分鐘後丟給你 500 行程式碼。

你高興地把程式碼合併到專案中……

**結果？**

三天後，品管發現：
- ❌ 密碼驗證規則和 PM 的期望不一致
- ❌ 少了「忘記密碼」功能
- ❌ Rate limiting 沒做
- ❌ 測試覆蓋率只有 30%
- ❌ 沒有考慮到帳號被鎖定的情況

大量返工。時間浪費。Agent 又被罵。

---

## 🎯 如果有正確的流程呢？

```
你：「讓我們用結構化的方式做這個。」

你：「/specify 使用者登入功能」
   Agent 生成清晰的規格

你：「/clarify」
   Agent 主動提出 5 個關鍵問題
   你們一起消除模糊點

你：「/plan」
   Agent 畫出完整的實作藍圖
   包括風險、邊界條件、測試策略

你：「/implement」
   Agent 按步驟執行
   每一步都驗證、每一步都有測試
   沒有驚喜，全是預期的結果

三天後，功能完成，品質達標，零返工。
```

**差別在哪？** 在於**流程**。

## 📚 這套手冊會教你什麼？

這不是一本傳統的教科書。

這是一本**動手做**的指南，用 O'Reilly Head First 的風格，帶你從零開始掌握：

### ✅ 核心三個概念
1. **SDD（規格驅動開發）** — 先說清楚「做什麼」
2. **BDD（行為驅動開發）** — 用使用者的語言描述期望
3. **TDD（測試驅動開發）** — 先寫測試再寫程式碼

### ✅ 實戰技能
- 用「四問題法」快速評估功能複雜度
- 根據複雜度選擇合適的工作流（Lite / Standard / Full）
- 寫出讓 Agent 能理解的結構化規格
- 用 Gherkin 語法寫出清晰的驗收測試
- 指導 Agent 逐步實作，每步驗證

### ✅ 真實案例
- 從簡單的樣式修改（Lite）
- 到新增 API 功能（Standard）
- 再到複雜的金流系統整合（Full）

每個案例都有完整的規格、情境、計畫、實作和驗證過程。

## 💡 你會學到的思維方式

### 從「吩咐」到「合作」

**舊方式**（吩咐型）：
```
「Agent，幫我做 X。」
Agent 直接做。
結果跟預期不符。
互相甩鍋。
```

**新方式**（合作型）：
```
「Agent，我想做 X。現在讓我們一起規劃。」
明確規格 ← 澄清誤會 ← 制定計畫
            ↓
        實作驗證 ← 反覆確認

結果符合預期。
你學到了什麼叫「好的溝通」。
```

### 從「相信 Agent」到「驗證 Agent」

不要盲目相信 AI 的輸出。**驗證**才是第一位。

每一步都問：
- ✅ 這個實作符合規格嗎？
- ✅ 測試都通過了嗎？
- ✅ 邊界條件有考慮嗎？
- ✅ 有遺漏的功能嗎？

## ⚡ 快速開始（5 分鐘版）

如果你很趕，可以直接跳到這裡：

### 第一步：評估複雜度（2 分鐘）

回答 4 個問題，每個 0-3 分：

```
Q1: 涉及多少模組或服務？(1=0分, 2+=2分)
Q2: 有權限、並發或不可逆操作嗎？(無=0分, 有=3分)
Q3: 涉及 DB Schema 變更嗎？(不=0分, 是=2分)
Q4: 涉及外部 API 整合嗎？(不=0分, 是=2分)

總分：___ 分
```

**0-2 分？** → 用 Lite 工作流
**3-5 分？** → 用 Standard 工作流
**6+ 分？** → 用 Full 工作流

### 第二步：按流程走（3 分鐘）

根據你的複雜度選擇：

**Lite** 工作流：
```
1. 簡單描述需求（1 句話）
2. Agent 直接實作
3. 驗證 + 完成
```

**Standard** 工作流：
```
1. 寫規格（spec.md）
2. 問澄清問題（/clarify）
3. 畫計畫（/plan）
4. 實作 + 測試（/implement）
```

**Full** 工作流：
```
1. 寫詳細規格 + 研究
2. 澄清所有模糊點
3. 制定完整計畫 + 分解任務
4. 按任務逐步實作
5. 整合驗證
```
