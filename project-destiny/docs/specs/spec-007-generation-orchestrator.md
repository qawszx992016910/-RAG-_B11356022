# Spec-007: 生成編排器

- Status: Draft
- Owner: NLP Engineer
- Last Updated: 2026-04-14

## 1. 目的

定義 LLM 生成前的證據整理、prompt 組裝、輸出約束與失敗處理。

## 2. 輸入

- 命盤摘要（來自 Bazi Engine）
- Rule Engine output（特徵、候選格局、風險旗標）
- Retrieval results（top-k atom + scores + reason_codes）
- 使用者語氣 / 輸出格式偏好（可選）

## 3. 核心責任

- 合併規則判定與文獻證據
- 限制模型只在證據範圍內生成
- 區分「判定」「引用」「解釋」三種內容類型
- 顯示不確定性

## 4. Prompt 區塊結構

### System Block
```
你是一位嚴格依據命理文獻的八字分析助理。
你的任務是根據以下提供的命盤資料、規則判定結果與文獻證據，
給出有根據的解盤說明。

規則：
- 只能根據提供的文獻與規則判定作出結論
- 不可自行創造不存在的古文或規則
- 不確定的部分必須明確說明
- 區分「規則判定」、「文獻引述」、「解釋說明」三種內容
```

### Context Block
```
【命盤資料】
{chart_summary}

【規則判定結果】
{rule_output_summary}

【相關文獻】
{retrieval_results_formatted}
```

### Output Format Block
```
請按以下格式輸出：
1. 命盤結構摘要
2. 核心判斷
3. 依據文獻
4. 規則說明
5. 綜合解釋
6. 不確定處
```

## 5. 輸出格式規範

```markdown
## 命盤結構摘要
[四柱、日主、月令、季節摘要]

## 核心判斷
[格局、強弱、調候方向]

## 依據文獻
- 《子平真詮》論甲木：「甲木參天，脫胎要火。」
  → [說明此句如何適用於本命盤]

## 規則說明
[規則引擎判定的格局候選與成立條件]

## 綜合解釋
[整合規則與文獻的完整解釋]

## 不確定處
[明示哪些判斷信心較低，原因為何]
```

## 6. 安全約束

- 不可自行創造不存在的古文
- 不可把推測寫成確定結論
- 不可跨來源硬拼矛盾結論
- 當證據不足時要明示不足，不自動補完
- 不可忽略 risk_flags 中的警示項

## 7. 驗收要求

- 主要結論皆有依據，可追溯至具體 atom
- 格式穩定，不隨 prompt 微調大幅漂移
- 不可出現明顯幻覺式補文
- 「不確定處」章節不可為空（永遠要誠實說明限制）

## 8. 依賴 ADR

- ADR-005：規則引擎先於生成層
- ADR-008：grounded generation 原則
