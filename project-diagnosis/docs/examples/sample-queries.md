# Sample Queries

以下範例搭配 `sql/tcm-rag.seed.sql` 的最小知識庫，可用於驗證 MVP pipeline。
每個範例給出：**輸入 → 預期抽取特徵 → 預期候選證型 → 系統應指出的關鍵差異或缺失**。

---

## Case 1：陰虛內熱典型

### 輸入

> 最近下午容易潮熱，晚上睡覺會盜汗，口乾，心煩，舌紅少苔。

### 預期抽取

- symptoms：潮熱、盜汗、心煩
- tongue：舌紅少苔
- time：午後、夜間
- missing：pulse_feature

### 預期 Top-3 候選

1. 陰虛內熱（強支持：盜汗 + 潮熱 + 舌紅少苔）
2. 肝腎陰虛
3. 心腎不交

### 規則觸發

- `TCM-RULE-001`（陰虛內熱核心三症）：boost +0.40 to 陰虛內熱
- `TCM-RULE-004`（缺脈象補問）：建議補問脈象

### 期望輸出重點

- 明確指出與肝腎陰虛的差異：後者通常伴腰膝酸軟、耳鳴
- 指出尚缺脈象資訊
- 不得直接推薦具體方劑

## Case 2：衛氣不固典型

### 輸入

> 容易自汗，吹風怕冷，精神疲倦，講話比較沒力，舌淡。

### 預期抽取

- symptoms：自汗、畏風
- signs：神疲
- tongue：舌淡
- missing：pulse_feature

### 預期 Top-3 候選

1. 衛氣不固（強支持：自汗 + 畏風 + 舌淡）
2. 肺氣虛
3. 陰虛內熱（應被 conflict 排除或顯著降分）

### 規則觸發

- `TCM-RULE-002`（衛氣不固核心三症）：boost +0.40 to 衛氣不固
- `TCM-RULE-004`：建議補問脈象

### 期望輸出重點

- 明確指出與肺氣虛的差異：後者伴咳嗽無力、聲低氣短
- 陰虛內熱因舌淡衝突應排在後段
- 不得因「汗」字就推向陰虛

## Case 3：矛盾訊號（氣陰兩虛疑似）

### 輸入

> 白天也出汗，晚上也出汗，口乾，精神不太好。

### 預期抽取

- symptoms：自汗、盜汗
- signs：神疲（可能未命中，視字典覆蓋）
- missing：tongue_feature、pulse_feature

### 預期行為

- `TCM-RULE-003`（陰虛氣虛主症衝突偵測）觸發
- 回傳 `ambiguity_flag`：「同時出現盜汗與自汗，需確認是否為氣陰兩虛」
- 建議問題：「自汗與盜汗哪個較明顯？是否有五心煩熱？」

### 期望輸出重點

- 候選應同時列出陰虛類與氣虛類，**不可**單押一邊
- 必須暴露不確定性，不做武斷判斷

## Case 4：術語查詢型

### 輸入

> 什麼是肝腎陰虛？

### 預期行為

- FTS 路徑主導（術語精確命中）
- 直接回傳 `atm_pattern_liver_kidney_yin_def` 的定義與常見表現
- 不應進入候選排序流程（或排序後只有一個結果）

### 期望輸出重點

- 回答應偏向解釋性
- 附上來源（中醫診斷學）

---

## Case 5：鑑別診斷型

### 輸入

> 自汗和盜汗怎麼分？

### 預期行為

- 同時檢索 `atm_symptom_zi_han` 與 `atm_symptom_dao_han`
- 組合兩者的「鑑別重點」段落
- 指出：自汗多日間、氣虛；盜汗多夜間、陰虛

### 期望輸出重點

- 必須是對比式呈現，不是兩段各自介紹
- 引用兩個 atom 的 body_markdown 中的鑑別段落

---

## 如何執行

```bash
# 在已套用 schema.sql + seed.sql，並跑過 embed_atoms.py 的環境下
export DATABASE_URL="postgresql://..."
export OPENAI_API_KEY="sk-..."   # optional

python scripts/answer_query.py "最近下午容易潮熱，晚上盜汗，口乾，舌紅少苔"
```

輸出為 JSON，可對照上述每個 Case 的「期望輸出重點」做人工驗證，
或整合進後續 evaluation harness（Phase 2 範圍）。
